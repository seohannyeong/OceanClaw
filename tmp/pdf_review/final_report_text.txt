작품 개요작품 정보    프로젝트명국문OceanClaw - 선박 정비 AI Agent작품명OceanClaw작품 소개OceanClaw는 선박 정비 현장의 장비 매뉴얼, 센서 이상 데이터, 정비 지식 문서를 통합 검색하는 로컬 기반 선박 정비 AI Agent이다. 사용자가 자연어로 질문하면 매뉴얼 PDF, 센서 이벤트 CSV, Obsidian Wiki에서 관련 근거를 검색하고, Ollama 기반 로컬 LLM으로 한국어 답변을 생성한다. 답변에는 매뉴얼 페이지와 출처를 함께 제공하여 사용자가 근거를 확인할 수 있도록 하였다.작품의개발배경 및 필요성선박 정비 업무에서는 장비 매뉴얼, 점검 절차, 센서 이상 이력 등 다양한 정보를 함께 확인해야 한다. 그러나 현장 자료는 PDF, CSV, 문서 파일 등으로 흩어져 있고, 긴 매뉴얼에서 필요한 내용을 빠르게 찾기 어렵다. 또한 선박 환경은 인터넷 연결이 불안정할 수 있어 외부 클라우드 API 의존에 한계가 있다. 이에 본 프로젝트는 매뉴얼과 센서 데이터를 검색 가능한 형태로 변환하고, Jetson Orin Nano에서 로컬 실행 가능한 정비 지원 AI 시스템을 구현하고자 하였다.
작품의특장점OceanClaw의 특장점은 선박 정비에 필요한 매뉴얼, 센서 데이터, 정비 지식을 하나의 AI Agent로 통합한다는 점이다. 사용자는 긴 PDF 매뉴얼을 직접 탐색하지 않고 자연어 질문으로 관련 절차와 근거를 확인할 수 있으며, 답변에는 매뉴얼 페이지와 Wiki 문서 출처가 함께 제공되어 신뢰성을 높였다. 또한 Ollama 기반 로컬 LLM과 Jetson Orin Nano 배포 구조를 적용하여 인터넷 연결이 제한적인 선박 환경에서도 활용 가능하도록 설계하였다. 향후 Gemini, 공공데이터 API, Mattermost, 실제 선박 센서와 연계하여 협업형·현장형 정비 지원 시스템으로 확장할 수 있다.
작품기능OceanClaw는 사용자가 자연어로 정비 질문을 입력하면 선박 매뉴얼 PDF, 센서 이벤트, Obsidian Wiki에서 관련 정보를 검색하고 한국어 답변을 제공한다. 답변에는 출처와 관련 페이지를 함께 표시하여 근거를 확인할 수 있다. 또한 질문과 답변 결과를 Wiki logs에 자동 저장해 정비 지식을 축적할 수 있다. FastAPI 서버와 Mattermost Slash Command를 통해 웹 API와 채팅창에서 모두 사용할 수 있으며, Jetson Orin Nano에서도 실행 가능한 로컬 정비 지원 시스템으로 구성하였다.작품의 기대효과 및 활용분야OceanClaw는 선박 정비 담당자가 긴 매뉴얼을 직접 탐색하지 않고도 필요한 점검 절차와 근거 페이지를 빠르게 확인할 수 있도록 지원한다. 이를 통해 정비 정보 탐색 시간을 줄이고, 센서 이상 상황에서 관련 매뉴얼과 점검 절차를 함께 확인할 수 있다. 또한 로컬 LLM 기반 구조이므로 인터넷 연결이 제한적인 선박 환경에서도 활용 가능하다. 향후 실제 정비 이력 데이터와 울산항만공사 공공데이터 API를 연계하면, 운항 상태를 고려한 점검 시점 안내와 정비 우선순위 판단 기능으로 확장할 수 있다.

본    문I. 작품 개요※ 평가항목 : 기획의 적절성 1. 작품 소개1) 기획의도 선박 정비 현장에서는 장비 매뉴얼, 센서 이상 데이터, 정비 기록 등 다양한 정보를 함께 확인해야 하나, 자료가 PDF, CSV, 문서 파일 등으로 분산되어 있어 필요한 정보를 빠르게 찾기 어렵다.OceanClaw는 이러한 문제를 해결하기 위해 선박 정비 자료를 통합 검색하고, 근거 기반 답변을 제공하는 로컬 AI Agent로 기획하였다.인터넷 연결이 제한적인 선박 환경을 고려하여 외부 클라우드 API 의존도를 줄이고,Ollama 기반 로컬 LLM과 FAISS 검색 구조를 적용하였다.단순 질의응답 챗봇이 아니라, 매뉴얼 페이지와 센서 이벤트, 정비 Wiki를 함께 참조하여 정비 담당자의 판단을 보조하는 시스템을 목표로 하였다.2) 작품 정의OceanClaw는 선박 정비 매뉴얼 PDF, 센서 이벤트 CSV, Obsidian 기반 정비 Wiki를 통합 검색하는 RAG 기반 선박 정비 AI Agent이다.사용자가 자연어로 질문하면 시스템은 관련 문서와 데이터를 검색하고, 검색된 근거를 기반으로 한국어 정비 답변을 생성한다.답변에는 가능한 경우 매뉴얼 페이지, 문서명, 검색 결과 등의 출처를 함께 제공하여 사용자가 AI 답변의 근거를 직접 확인할 수 있다.NVIDIA Jetson Orin Nano Super Developer Kit에서 FastAPI 서버로 실행할 수 있도록 구성하여, 엣지 환경에서의 활용 가능성을 고려하였다.3) 작품 내용PDF 매뉴얼 처리- 선박 엔진 매뉴얼 PDF에서 페이지 단위로 텍스트를 추출한다.- 추출된 텍스트는 chunk 단위로 분할하여 검색에 적합한 문서 조각으로 변환한다.Vector Search 기반 검색- 문서 chunk를 Ollama embedding 모델을 통해 vector로 변환한다.- 생성된 vector는 FAISS index에 저장하여 사용자 질문과 의미적으로 유사한 문서를 빠르게 검색한다.센서 데이터 검색- 원본 CSV 데이터를 정비 이벤트 형식의 sensor_events.csv로 변환한다.- 센서 이상 이벤트도 embedding하여 매뉴얼과 함께 검색 가능한 데이터로 활용한다.

RAG 기반 답변 생성- 검색된 매뉴얼 chunk와 센서 이벤트를 context로 구성한다.- Ollama chat 모델을 이용해 한국어 정비 답변을 생성하며, 답변에는 출처와 관련 페이지를 함께 제공한다.Obsidian Wiki 연동- 정비 절차와 지식을 Markdown 문서로 저장할 수 있는 Wiki 구조를 구성하였다.- Obsidian에서 직접 열람할 수 있으며, 향후 Wiki 문서도 답변 생성에 활용할 수 있도록 검색 index 기반을 마련하였다.Jetson 배포- Jetson Orin Nano에서 FastAPI 서버를 실행할 수 있도록 구성하였다.- 같은 네트워크의 PC에서 Jetson 서버에 접속하여 검색 및 답변 기능을 사용할 수 있도록 하였다.이후 구현 예정- Mattermost 실제 채널 연동 완료  - 현재 구현된 /mattermost/slash endpoint를 Mattermost Slash Command와 완전히 연결한다.  - 팀원이 Mattermost 채팅창에서 /oceanclaw 명령어로 질문하면 OceanClaw 답변이 채널에 표시되도록 테스트 및 안정화한다.- 실제 선박 센서 연동  - 현재는 공개 CSV 데이터를 센서 이벤트로 변환하여 사용하고 있다.  - 향후 온도, 압력, 진동, RPM 등 실제 센서 데이터를 Jetson에서 수집하고, 이를 정비 이벤트로 변환하여 RAG 검색에 활용할 예정이다.- 공공데이터 API 연계  - 울산항만공사 선박 운항정보, 선박제원정보 등 공공데이터 API를 연계할 예정이다.  - 선박 운항 상태와 제원 정보를 참고하여 점검 시점 안내나 정비 우선순위 판단 기능으로 확장할 수 있다.- 검색 품질 개선  - 현재는 Ollama embedding과 FAISS 기반 dense retrieval을 중심으로 검색한다.  - 향후 BM25 기반 sparse search, hybrid search, reranker 등을 도입하여 부품명, 고장 코드, 전문 용어 검색 성능을 높일 예정이다.- 사용자 화면 개선  - 현재는 CLI, FastAPI Swagger UI, Mattermost 연동을 중심으로 테스트하고 있다.  - 향후 질문 입력창, 답변 화면, 출처 표시, 검색 결과 확인 기능을 포함한 웹 UI를 구현할 예정이다.- Jetson 운영 안정화  - Jetson 서버 자동 실행 설정, IP 고정 또는 Tailscale/ngrok 기반 외부 접속 구성을 추가할 예정이다.  - 이를 통해 팀원이 같은 네트워크가 아니어도 OceanClaw 서버에 접속할 수 있도록 개선한다.- 검색 평가 자동화  - 질문 세트와 기대 출처를 정의하고, top-k 검색 결과가 기대 결과와 일치하는지 자동 평가하는 기능을 추가할 예정이다.  - 이를 통해 검색 정확도와 답변 품질을 정량적으로 확인할 수 있도록 한다.

 2. 작품의 개발 배경 및 필요성 1) 작품 제작 동기선박 정비 업무는 장비 고장이나 이상 상황 발생 시 빠른 판단과 정확한 절차 확인이 중요하다.그러나 정비 담당자는 긴 PDF 매뉴얼, 센서 로그, 과거 정비 기록을 각각 따로 확인해야 하므로 정보 탐색에 많은 시간이 소요된다.특히 신규 정비 인력의 경우 매뉴얼 구조와 장비 용어에 익숙하지 않아 필요한 정비 절차를 찾는 데 어려움이 있다.선박 환경은 인터넷 연결이 항상 안정적이지 않기 때문에, 외부 AI API에 의존하는 시스템은 실제 현장 적용에 제약이 있을 수 있다.이러한 문제를 해결하기 위해 로컬 환경에서 동작하며, 선박 정비 자료를 통합 검색할 수 있는 AI Agent가 필요하다고 판단하였다.2) 작품 제작 목적선박 정비 매뉴얼 PDF에서 필요한 절차와 주의사항을 빠르게 검색할 수 있는 구조를 구현한다.센서 이상 데이터와 매뉴얼 근거를 함께 활용하여 정비 판단을 보조한다.AI 답변에 출처와 페이지 정보를 포함하여 사용자가 원문 근거를 검증할 수 있도록 한다.Ollama 기반 로컬 LLM을 사용하여 API 비용과 인터넷 의존도를 줄인다.Jetson Orin Nano에서 실행 가능한 구조를 구성하여 엣지 AI 기반 선박 정비 지원 시스템의 가능성을 확인한다.Obsidian Wiki를 활용하여 정비 지식을 지속적으로 축적하고 검색할 수 있는 기반을 마련한다.3) 필요성정비 정보 탐색 시간 단축- 긴 매뉴얼에서 필요한 내용을 직접 찾는 시간을 줄일 수 있다.정비 의사결정 보조- 센서 이상 데이터와 매뉴얼 절차를 함께 확인하여 정비 판단을 지원할 수 있다.로컬 실행 가능성 확보- 인터넷이 불안정한 선박 환경에서도 AI 기반 정비 지원 기능을 사용할 수 있다.지식 축적 체계 마련- Obsidian Wiki를 통해 정비 절차, 고장 사례, 작업 기록을 체계적으로 저장할 수 있다.교육 및 실습 활용- 신규 정비 인력이나 학생들이 선박 정비 절차를 학습하는 데 활용할 수 있다.

OceanClaw는 선박 매뉴얼 PDF, 센서 이벤트 CSV, Obsidian Wiki를 통합 검색하여 정비 질문에 답변하는 로컬 AI Agent이다. 사용자의 자연어 질문은 검색용 query로 변환된 뒤 Manual/Sensor/Wiki index에서 관련 근거를 찾고, Ollama 기반 로컬 LLM이 이를 바탕으로 한국어 답변을 생성한다. 답변에는 출처와 관련 페이지를 함께 제공하여 사용자가 근거를 확인할 수 있도록 하였다.2. 주요 적용 기술 1) RAG 기반 선박 정비 질의응답 기술본 작품의 핵심 기술은 RAG(Retrieval-Augmented Generation) 구조이다. RAG는 LLM이 자체 지식만으로 답변하지 않고, 외부 문서나 데이터베이스에서 관련 정보를 먼저 검색한 뒤 해당 정보를 바탕으로 답변을 생성하는 방식이다.선박 정비 분야는 안전과 관련된 정보가 많기 때문에, LLM이 근거 없이 임의로 답변을 생성하는 방식은 위험할 수 있다. 따라서 OceanClaw는 매뉴얼 PDF와 센서 이벤트 CSV를 먼저 검색하고, 검색된 근거를

3) Chunk 분할 기술PDF 한 페이지 또는 전체 문서를 그대로 embedding하면 검색 단위가 너무 커져 정확도가 떨어질 수 있다. 따라서 OceanClaw는 문서를 일정한 크기의 chunk로 나누어 검색 단위로 사용하였다.Chunk 분할에는 LangChain의 RecursiveCharacterTextSplitter를 활용하였다. 이 방식은 단순 글자 수 기준으로 자르는 것보다 문단, 줄바꿈, 문장 경계를 우선 고려할 수 있다는 장점이 있다.PDF page text -> chunk 1 -> chunk 2 -> chunk 3또한 chunk overlap을 적용하여 문서가 잘리는 경계에서 중요한 문맥이 사라지지 않도록 하였다.4) Embedding 및 Vector SearchEmbedding은 텍스트의 의미를 숫자 벡터로 변환하는 기술이다. 사용자의 질문과 문서 chunk를 같은 vector 공간에 배치하면, 의미적으로 비슷한 문서를 검색할 수 있다.OceanClaw는 Ollama embedding 모델을 사용하여 문서 chunk와 질문을 vector로 변환하고, 변환된 vector를 FAISS index에 저장하였다.문서 chunk -> Ollama Embedding -> Vector -> FAISS Index사용자가 질문하면 질문도 embedding으로 변환하고, FAISS에서 가장 유사한 chunk를 top-k 방식으로 검색한다. FAISS는 대규모 vector 검색에 적합한 라이브러리로, 로컬 환경에서 빠른 검색이 가능하다는 장점이 있다.5) Query Expansion실제 선박 매뉴얼은 영어로 작성된 경우가 많지만, 사용자는 한국어로 질문할 가능성이 높다. 초기 검색 테스트에서 “엔진 오일 점검 방법”이라는 한국어 질문은 정확한 페이지를 찾지 못했지만, “engine oil level check dipstick MIN MAX”와 같은 영어 표현을 포함하면 정확도가 크게 향상되었다.이를 해결하기 위해 OceanClaw는 query expansion을 적용하였다.입력 질문:엔진 오일 점검 방법 알려줘확장 질문:엔진 오일 점검 방법 알려줘engine oil level dipstick MIN MAX check inspect procedure이 방식은 한국어 질문과 영어 매뉴얼 사이의 표현 차이를 보완하여 검색 정확도를 높인다.

Ollama를 사용하면 API 비용과 인터넷 의존도를 줄일 수 있었지만, Jetson 환경에서는 응답 속도, timeout, 모델 크기 선택과 같은 현실적인 문제가 발생하였다. 이를 통해 실제 현장 적용에는 모델 성능뿐 아니라 하드웨어 성능과 운영 환경까지 함께 고려해야 한다는 것을 느꼈다.데이터의 중요성도 크게 느꼈다. 코드가 정상적으로 동작해도 적절한 매뉴얼과 센서 데이터가 없으면 좋은 답변을 만들기 어렵다. 특히 선박 정비 데이터는 공개적으로 구하기 쉽지 않아, 데이터 수집과 정제, 평가 질문 설계가 프로젝트 품질에 큰 영향을 준다는 것을 알게 되었다.문제를 단계별로 검증하는 습관의 중요성을 배웠다. 답변이 이상할 때 바로 LLM 문제로 판단하지 않고, PDF 추출 결과, chunk 결과, 검색 결과, prompt를 차례대로 확인해야 했다. USB 설치, 모니터 연결, SSH 접속, IP 확인, 패키지 설치, 서버 실행 등 운영 환경을 직접 구성하면서 로컬 PC에서 코드가 동작하는 것과 실제 장비에서 서비스로 실행하는 것은 다르다는 점을 배웠다.최종적으로 OceanClaw를 개발하면서 스마트해운물류 분야에서 AI가 실질적으로 활용될 수 있다는 가능성을 확인하였다. 선박 정비는 전문 용어와 절차가 많고 자료가 복잡하기 때문에, 근거 기반 검색과 답변 생성이 현장 업무를 보조하는 데 도움이 될 수 있다고 느꼈다. 향후 실제 선박 정비 데이터와 공공데이터 API를 연계한다면 더 실용적인 현장형 정비 지원 시스템으로 발전시킬 수 있을 것이다.
